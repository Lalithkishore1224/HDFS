The Drive API, explained simply

Every button in the app sends a small message to the server. This page shows each message, the answer it gets back, and what really happens behind the scenes, using real examples.

Read this first: what is an API?

Think of a restaurant. You (the app) look at the menu and tell the waiter (the API) what you want. The waiter takes your order to the kitchen (the server) and brings back a reply. You never go into the kitchen. The API is the list of orders the waiter understands, and the replies you can expect.

What you send

An action and an address, and sometimes some details:

  • GET: show me something
  • POST: create something, or do something
  • PATCH: change something
  • DELETE: remove something

What you get back

A status number and usually some data:

  • 2xx: it worked
  • 4xx: you asked for something the server cannot accept
  • 5xx: the server could not do it right now

Who is asking

The server needs to know who you are:

  • You sign in once and get a session cookie
  • Changes also need a CSRF token
  • Some actions are for administrators only

How a file is stored: the distributed part

A file is not saved in one place. It is cut into pieces, and every piece is kept on three different storage nodes.

What you can see in the table

  • Every piece has three dots: three copies on three different nodes.
  • No node holds the whole file.
  • Different pieces use different nodes, so the load is spread out.

What happens when nodes fail

  • Stop node-2 and node-3 together: every piece still has at least one copy left.
  • The download in step 18 returned the same bytes (identical fingerprint).
  • The server then re-creates the missing copies by itself ("repair").

1 · Cut

The file is split into 256 KiB pieces called chunks, plus a small manifest saying how many.

2 · Spread

Each chunk goes to 3 of the 5 nodes, picked by a hash of the chunk's id. No lookup table is needed: the same hash finds it again later.

3 · Heal

A heartbeat notices a dead node within seconds, and repair re-creates the lost copies on the nodes that still work.

Try it yourself

Two things identify every call: a session cookie, and, on anything that changes data, a CSRF header.

Session cookie

You receive JSESSIONID when you sign in. Send it back on every call; curl -b cookies.txt does this for you.

CSRF header

The server sets an XSRF-TOKEN cookie. For POST, PATCH and DELETE, send its value as the X-XSRF-TOKEN header. GET requests do not need it.

Setup: run once
# 1. Pick a base URL and let curl keep the cookies in a file
BASE=http://localhost:8080

# 2. Any GET gives you the XSRF-TOKEN cookie
curl -s -c cookies.txt "$BASE/api/auth/config"

# 3. Read the token out of the cookie file (used for every POST / PATCH / DELETE)
TOKEN=$(grep XSRF-TOKEN cookies.txt | awk '{print $7}')

# 4. Sign in (or create the account first with POST /api/auth/register)
curl -s -b cookies.txt -c cookies.txt -X POST "$BASE/api/auth/login" \
  -H "X-XSRF-TOKEN: $TOKEN" -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<your password>"}'

# 5. The session cookie changed; refresh the token before the next write
TOKEN=$(grep XSRF-TOKEN cookies.txt | awk '{print $7}')

Good to know

  • Folders are virtual. Creating, renaming and moving a folder only changes database records; no file data moves.
  • Someone else's items answer 404, not 403. It avoids confirming that an id exists.
  • Storage tiers are invisible to users on purpose. A rarely used file may be compressed ("cold"); opening it restores it automatically. Only the admin endpoints show tiers.
  • Two storage nodes may fail at the same moment without any file becoming unreadable. Three failing together can make the pieces they alone held unreadable until one returns (HTTP 503).
  • In this setup all five nodes run on one computer (as Docker containers), so a failure of the whole computer is not covered.
  • Passwords are stored as BCrypt hashes only. Use HTTPS in front of the server so passwords are not sent in clear text, and set the administrator usernames in the server settings.
